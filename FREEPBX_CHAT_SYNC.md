# FreePBX ↔ Tvoice Chat: единая авторизация

## Что уже делает Android-клиент

Пользователь вводит одну пару `SIP-номер + пароль`. Tvoice сначала подтверждает эту пару реальной
SIP-регистрацией на FreePBX. Только после успешной SIP-регистрации те же значения отправляются в
`POST /v1/auth/login` чат-сервера:

```json
{ "sipNumber": "73302", "password": "<тот же пароль FreePBX>" }
```

Пароль не записывается в логи и не сохраняется чат-клиентом отдельно. Произвольное клиентское
ограничение минимальной длины пароля удалено: действительный короткий пароль FreePBX теперь тоже
доходит до сервера.

## Текущее состояние production

Развёрнут `tvoice-chat 0.3.1`. FreePBX является источником учётных данных:

- закрытый endpoint на `10.10.10.2` доступен только от чат-сервера `10.10.10.6`;
- вход в чат всегда проверяет актуальный SIP-пароль в FreePBX;
- номер и отображаемое имя синхронизируются при запуске, каждые пять минут и после входа;
- сейчас синхронизированы 19 из 19 активных абонентов;
- SIP-пароли не возвращаются каталогом и не записываются в PostgreSQL чата.

## Реализованный поток входа

Обработчик `/v1/auth/login`:

1. Нормализовать `sipNumber` теми же правилами, что SIP endpoint ID.
2. Передаёт номер и пароль приватному FreePBX auth bridge.
3. Проверять пароль на стороне доверенной серверной сети — через отдельный PBX auth adapter либо
   другую поддерживаемую сервером проверку SIP credentials.
4. После успешной проверки атомарно создаёт или обновляет пользователя чата и выдаёт JWT.
5. При смене пароля в FreePBX немедленно принимать новый пароль и отклонять старый.
6. Хранит для FreePBX-пользователей только признак внешнего источника авторизации.

Псевдокод обработчика:

```text
POST /v1/auth/login
  input = validate(sipNumber, password)
  if !freePbxAuth.verify(input.sipNumber, input.password):
      return 401 { error: "invalid_credentials" }
  user = chatUsers.upsertBySipNumber(input.sipNumber)
  contacts.syncFromFreePbxDirectory(user)
  return 200 { accessToken: tokens.issue(user, shortTtl) }
```

PBX adapter ограничен IP чат-сервера и отдельным случайным служебным ключом. MariaDB и AMI наружу
не открыты; между VM используется изолированная сеть `10.10.10.0/24`.

## Приёмочная проверка

- правильный реальный SIP-пароль проходит end-to-end с HTTP 200;
- заведомо неверный пароль отклоняется с HTTP 401;
- каталог содержит 19 из 19 учётных записей FreePBX;
- Неверный пароль отклоняется обоими сервисами.
- После смены пароля FreePBX старый пароль перестаёт работать в чате.
- Новый extension появляется в `GET /v1/contacts` без ручного добавления в базу чата.
- Два абонента создают direct conversation, обмениваются сообщениями и получают WSS-события.
- Удалённый/заблокированный extension больше не получает новый чат-токен.
